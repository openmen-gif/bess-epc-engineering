### Vendor-DB 필드 스키마 (Process — 마스터 데이터 표준)
> 모든 레코드는 아래 스키마를 따른다. 필수 필드 미충족 레코드는 등록 보류(Pending) 처리하고 [요확인] 태그를 부착한다. 단가·인증 등 출처 의존 필드는 검증 통과 전까지 신뢰도 미확정으로 간주한다.
| 필드명 | 타입 | 필수여부 | 예시 | 검증규칙 |
|--------|------|----------|------|----------|
| vendor_id | String(PK) | 필수 | `VD-KR-00231` | 고유값, 중복 0건, 정규식 `^VD-[A-Z]{2}-\d{5}$` |
| 업체명 | String | 필수 | `LG에너지솔루션` | 공백/특수문자 정규화, 동일 법인 중복 ≤1% |
| 국가 | Enum(ISO 3166-1) | 필수 | `KR` | KR/JP/US/AU/UK/EU/RO/PL 8개 코드 외 입력 거부 |
| 품목(HS코드) | String(6~10자리) | 필수 | `850760` (리튬이온 축전지) | HS 6자리 이상, 품목 매핑표와 일치 |
| 인증 | List<Enum> | 필수 | `UL9540A, IEC62619` | UL9540A·IEC62619·UL1973·IEC62933 등 허용목록, 만료일 ≥ today |
| 인증_만료일 | Date | 필수 | `2027-03-31` | ISO 8601, 만료 90일 전 자동 알림 |
| 단가 | Decimal+통화 | 필수 | `92.5 USD/kWh` | >0, 통화코드(USD/KRW/EUR 등) 필수, 기준일 동반 |
| 단가_기준일 | Date | 필수 | `2026-05-29` | ISO 8601, 최근 90일 이내 권장(초과 시 [요확인]) |
| 리드타임 | Integer(주) | 필수 | `12` (주) | 0<x≤104주, 단위(주) 고정 |
| MOQ | Integer+단위 | 선택 | `1 컨테이너 (3.7MWh)` | >0, 단위 명시(set/MWh/ea) |
| 납기준수율 | Percent | 필수 | `96.2%` | 0~100%, 산출식 동반(아래 KPI 참조) |
| 품질합격률 | Percent | 필수 | `98.7%` | 0~100%, LOT 기반 산출 |
| 연락처 | String(email/tel) | 필수 | `sales@vendor.com` | 이메일 정규식 또는 E.164 전화 포맷 |
| 갱신일 | Date(audit) | 필수 | `2026-06-08` | ISO 8601, 변경 시 자동 기록 |
> [가정] 단가 예시값 `92.5 USD/kWh`는 표 형식 설명용 placeholder이며 실거래가 아님 — 실값은 단가 출처 위계(공급사 공식 → BNEF/Wood Mackenzie → IEA) 교차검증 후 입력. [요확인] HS코드 `850760`은 리튬이온 축전지 기준이며 품목별 세번 분류는 통관·물류전문가 확정 필요.
### KPI 산출식 및 임계치 (Process — 벤더 성과 정량화)
| KPI | 산출식 | 목표(Pass) | 불합격(Fail) 조치 |
|-----|--------|------------|-------------------|
| 납기준수율 | (정시납품 건수 / 총납품 건수) × 100 | ≥95% | <95% → 벤더 등급 강등·SCM 통보 |
| 품질합격률 | (합격 LOT 수 / 총 입고 LOT 수) × 100 | ≥98% | <98% → QA/QC NCR 연계·시정요청 |
| 가격경쟁력 | (1 − 벤더단가 / 시장평균단가) × 100 | 시장평균 대비 0% 이상(저렴) | 시장평균 +5% 초과 → 재협상 권고 |
| 데이터완전성 | (필수필드 충족 레코드 / 전체 레코드) × 100 | ≥98% | <98% → 미충족 레코드 [요확인]·보완 |
> 보조 정합성 지표: **중복률 = (중복 레코드 수 / 전체 레코드 수) × 100 ≤ 1%** (vendor_id·업체명+국가 복합키 기준). 가격경쟁력의 시장평균단가는 BNEF/Wood Mackenzie 분기 데이터 기준이며 출처·기준일을 항상 병기한다. 4개 KPI는 벤더 성과 카드에 수치+단위로 표기하고 비정량 판정(양호/적정)은 금지한다.
> 종합 벤더 스코어(가중 예시, [가정]): 납기준수율 35% + 품질합격률 35% + 가격경쟁력 20% + 데이터완전성 10%. 가중치는 프로젝트 조달정책에 따라 구매전문가와 협의 조정 — 본 직무는 데이터·점수 산출만 담당하고 선정 결정은 하지 않는다.
### 데이터 거버넌스 / Audit-Trail 절차 (Process — 입력→검증→승인→이력보존)
```
마스터 데이터 라이프사이클 (4단계)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
1. 입력 (Entry)
   ├── 스키마 필드 입력 (필수 13필드 충족 확인)
   └── 출처 메타 동반 (단가 출처·기준일, 인증 발급기관)
2. 검증 (Validation)
   ├── 자동 검증: 타입·정규식·중복(≤1%)·필수필드(≥98%)
   ├── 인증 만료일 ≥ today, 단가 기준일 ≤90일
   └── Fail 시 → 등록 보류(Pending) + [요확인] 태그
3. 승인 (Approval)
   ├── 검증 통과 레코드만 승인 대기 큐 진입
   └── 데이터 오너 승인 → Active 상태 전환 (4-eyes 원칙 권장)
4. 이력 보존 (Audit Trail)
   ├── 변경 항목: who(작성자) / when(타임스탬프) / what(필드·전후값) / why(사유)
   ├── 보존 기간 ≥ 계약·조달 기록 법정 보존기간([요확인] 시장별 상이)
   └── 원본 불변(immutable log), 수정은 신규 버전으로만
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```
> [요확인] 조달 기록 법정 보존기간은 시장별 상이(예: 다수 관할에서 5~10년 수준)하므로 법률·세무전문가 확정 후 적용. 감사 추적 로그는 내부감사(bess-internal-auditor)의 조달 감사 증적으로 직접 활용된다.
